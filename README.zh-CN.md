## 🚀 主项目

### [WaySlice](https://wayslice.cn)

> **Telemetry for every way. Sliced.**
> **所经之路，皆成遥测；所成遥测，皆可切析。**

一个开源的 Web 运动记录分析工具，核心理念是：

**分段分析（Sector-based Analysis）** 和 **遥测数据（Telemetry）**

关键词：

- 🗺️ GPX / KML / KMZ / TCX / FIT 文件解析
- 📏 水平距离与 3D 距离
- ⏱️ 时间、配速与分段分析
- ⛰️ 海拔、累计爬升 / 下降与坡度
- ❤️ 心率区间与遥测数据
- 🚴 骑行 / 🏃 跑步 / 🥾 徒步
- 🧭 多地图图源
- 🌍 公制 / 英制 单位转换
- 🌐 多语言界面
- 💻 只需要浏览器，没网也能跑。你的数据，只有你知道。

你的运动记录，不应该只是一条画在地图上的线，而是可视化、可分段分析的遥测数据。

→ [使用 WaySlice](https://wayslice.cn)

## 🤖 AI × Software Development

我目前也在研究 AI 如何改变软件开发。

以下是我在选择工具时的考虑方向：

- Coding Agent
- 不同语言模型在不同任务中的分工
- 模型 API 供应商
- 模型智能 / 速度 / 成本
- 接入语言模型后的开发环境
- 长上下文工作流
- 基于文件和目录的工作流
- AI 辅助翻译与文档处理
- 提示词设计

我也喜欢**围绕自己真正关心的任务做模型评测**，比如针对特定专业领域文本的翻译质量、图片理解和推理能力，以及对冷门梗的识别，而不是只看跑分榜单。

在选择模型时，我会在以下方面做出权衡：

**智能 × 速度 × 成本 × 上下文长度 × 可靠性**

我不认为存在一个永远的“最佳模型”。

我更感兴趣的是：

> **对于特定的任务，哪个模型才是有效前沿上的最佳选择？**
